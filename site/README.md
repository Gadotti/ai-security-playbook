# Explorer site

A static, single-page visual explorer for this repo: the guided path, the OWASP LLM Top 10 risk map, runnable labs, the interactive checklist and maturity board, policy simulators, full-text search, and every external citation. It is additive — nothing outside `site/` depends on it, and it never duplicates repo content: it reads the repo's own Markdown and code from a generated bundle.

## Open it

- **Locally, no server:** open `site/index.html` in a browser (works over `file://`).
- **Locally, with a server** (closer to GitHub Pages): `python -m http.server 8000 --directory site`, then browse to `http://localhost:8000`.
- **GitHub Pages:** see [Deploy](#deploy).

## Disclaimer

The home page shows the same notice as the repo README: the content was produced and organized with the help of AI tools and is still under validation. A short version stays in the sidebar on every page. The text lives in `assets/app.js` (`disclaimer` / `disclaimerShort`, EN and PT).

## What runs where

A static page can't start processes on your machine, so "running" a lab means one of three things:

| Lab / item | In the page |
|---|---|
| `labs/ai-jail` | **Runs in the browser.** Real `tool_gateway.py` + `demo_agent.py`, executed by Python compiled to WebAssembly ([Pyodide](https://pyodide.org/) v0.26.4). Files are editable before each run. |
| `labs/injection-tests` | **Runs in the browser**, same way, with the `--category` argument and the real `test_cases.yaml` (PyYAML is loaded by Pyodide). Still hits the stub `mock_target()` unless you edit it. |
| `labs/prompt-anonymizer` | **Didactic JavaScript simulator** of the mask → call → re-hydrate round trip, using simple heuristics. The real PoC depends on Presidio + spaCy models, which don't run in the browser. The simulator is for understanding the flow and its failure modes, never for protecting real data. |
| `labs/skillspector-scan`, policy hooks | **Command builder** — pick options, copy the exact command (bash or PowerShell). |
| `policies/*.yaml` | **Simulators** that read the YAML live: tool-allowlist decisions and spend-cap hard stops vs. alerts. |

Pyodide is only downloaded (about 10 MB, from jsDelivr) the first time you press **Run**. Code runs locally in the browser tab. Nothing is sent anywhere else. Running the non-browser labs for real still means cloning the repo. A local runner that executes commands would have to be a separate app with a server.

## Update the content

The pages read `data/content.js`, generated from the repo by a standard-library-only script:

```bash
python site/build.py
```

Re-run it after editing any file outside `site/` if you view the site locally. The Pages workflow runs it on every deploy, so the published site is always in sync with `main`.

What gets bundled: every git-tracked text file outside `site/` (`.md`, `.py`, `.yaml`, `.sh`, `Dockerfile`, …), plus images as data URIs. Untracked files are skipped.

## Deploy

[`.github/workflows/pages.yml`](../.github/workflows/pages.yml) builds the bundle and publishes `site/` on every push to `main`:

1. Make the repository public. The job is skipped while the repo is private, so pushes don't fail before Pages is set up.
2. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
3. Push to `main` (or run the workflow manually). The site is served at `https://<owner>.github.io/<repo>/`.

## How it's built

```
site/
├── index.html            page skeleton + visual style (--pb-* tokens, light/dark) + Playbook.init()
├── assets/app.js         engine: router, views, Markdown rendering, search, runners, simulators
├── assets/core.css       structural styles, fully driven by --pb-* CSS variables
├── data/content.js       generated by build.py — do not edit
├── vendor/               pinned third-party libraries (see vendor/README.md)
└── build.py              bundle generator (stdlib only)
```

- **Routes** are hash-based (`#/risk/LLM01`, `#/lab/ai-jail`, `#/doc/<path>@<heading>`), so they work on any static host and over `file://`.
- **Links inside docs** are rewritten to in-app routes. A link to a file that isn't bundled falls back to GitHub.
- **Derived, not duplicated:** the risk list and layers come from `docs/owasp-llm/README.md`, the checklist from `docs/framework/checklist.md`, maturity levels from `docs/framework/maturity-model.md`, policy simulators from the YAML files, "referenced by" panels and the citation index from the links in every doc, and the `[to verify]` list from the markers themselves. Editing those files updates the site.
- **Authored in the engine:** the guided path's step texts (EN/PT) and the lab command templates. Every external link they use is one the repo already cites.
- **UI language:** English or Portuguese (auto-detected, toggle in the top bar). The repo content itself stays in English.

### Changing the look

[index.html](index.html) provides the slots the engine fills — `#pb-nav`, `#pb-view` (required), `#pb-search`, `#pb-tools`, `#pb-crumbs`, `#pb-status` — loads the scripts in order, and calls `Playbook.init()`. Optional settings:

```js
Playbook.init({
  navIcons: true,
  navLabels: {},          // optional per-item label overrides, { home: { en, pt } }
  onRender(route, el) {}  // optional hook after each render
});
```

Everything else is CSS: redefine the `--pb-*` tokens from `assets/core.css` and style the `.pb-*` classes the engine emits.

## Security notes

- Third-party JS is **vendored and pinned** (versions + SHA-256 in [vendor/README.md](vendor/README.md)). The only runtime CDN load is Pyodide, and only when you press **Run**.
- Rendered Markdown is sanitized with DOMPurify. External links open with `rel="noopener noreferrer"`.
- Checklist answers, maturity levels, journey progress, and UI preferences are saved in the browser's `localStorage` only. There's no backend, analytics, or tracking. Use the export buttons to move answers into your own tracker.
- Payloads in `labs/injection-tests/test_cases.yaml` are displayed as escaped text, never rendered as HTML.
